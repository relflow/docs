# Numeric predictive-grouping combination evidence

All 48 predefined fits completed: four recipes, four numeric processes, three
seeds (7901–7903), 600 optimizer updates each. The unchanged P079 baseline is
followed by deterministic hard straight-through routing, assignment initialization
scale 0.1, and proposal margin 1. Each row adds the named change to the previous
recipe. The frozen `protocol.json` and harness identify the exact methods.
Production code and canonical proof results were not changed by this matrix.

| --- | ---: | ---: | ---: |
| Predictive baseline | 7/12 | 7/12 | 11/12 |
| + deterministic ST | 8/12 | 8/12 | 12/12 |

Full gates require ARI at least 0.8, normalized RMSE at most 0.35, exact occupied
group count, shuffled error at least 0.85, and shuffling error increase at least
0.4. Quality means the first two gates. Error is divided by the training-mean
constant predictor's error: 1 is constant-guess performance, lower is better.
ARI 1 means the same partition after allowing arbitrary group label names.

The strongest stack improves six-group recovery to ARI 1 and six occupied groups
in every seed, with fresh error ratios 0.0327–0.0391 (baseline 0.2286–0.2628).
It also passes all crossing-curve and separated-four seeds. Imbalance remains a
failure: only one of three seeds recovers the exact count; seed 7901 has ARI
0.535 despite an acceptable global error ratio 0.223. Smaller initialization
without margin 1 also solves all six-group seeds but splits a crossing group in
seed 7901 and merges groups in two imbalanced seeds. No recipe solves this
entire bounded matrix.

## Validation and interpretation boundaries

Cases, seeds, methods and thresholds were frozen before the first fit. A proposal
uses only per-identity conditional training errors and is accepted only if
validation MSE improves. Validation is reused for development and is tuning data.
After all validation files finished, a separate command froze their hashes and
audited every checkpoint on 2,048 independently generated known-identity rows
using stream `seed*100+10003`, retaining the same generating partition. Original
P079 test stream 3 is never generated by this harness. Every arm, including
quality failures, received that audit; there was no audit-based retraining or
variant filtering. All parameter/buffer/assignment preservation assertions passed.
Group-label permutation diagnostics and shuffled-control measurements are in the
raw audit JSON. Existing baseline assignment arrays and intervention acceptance
flags reproduce canonical P079 exactly in all 12 matched cases.

Removing Gumbel draws changes later masking/dropout RNG draws even at the same
seed. Baseline-versus-ST comparisons therefore compare complete training recipes,
not a perfectly RNG-matched routing-only causal intervention. The three ST recipes
share the same RNG draw protocol relative to one another. This matrix excludes
no-regime fits and is not a complete canonical proof panel or a universal capacity
recovery claim. It remains a root-only numeric residual diagnostic; integrating
it generically requires extension-owned losses and identity/geometry attribution.
Recorded wall times use concurrent CPU load and are not an isolated benchmark.
The separate P081 +28.60% result concerns the original predictive recipe, not a
measured cost for these combinations.

## Contents and reproduction

The archive preserves all validation/audit JSON, per-seed logs, summary and
summary source, frozen harness/protocol/P079/helper sources, environment metadata,
the exact Group source for reference, and every checkpoint SHA-256. It excludes
trained checkpoint binaries, caches, lock files and duplicate full package
snapshots. `FILE_SHA256.json` records payload integrity; sibling `manifest.json`
records the archive digest and every member digest/size. Tar metadata and gzip
mtime are normalized. Every archived member was read back and verified.

The package source dependency is the separate docs archive
`proofs/group/diagnostics/expansion-2026-10-17/experiments.tar.gz`, SHA-256
`adab27f329b5909aa39a2390fd683b7b9d72b287ac871a87c99a3459a6f4c6fe`.
It contains `group-expansion-20261017/snapshot`, with source-tree digest
`4f900097c5f12eb6eef07e88b7abba5c61089f52696d52ee8c08d105894a5b58`.
Unpack both archives into an empty directory, then link that snapshot into the
combination directory:

```bash
ln -s ../group-expansion-20261017/snapshot group-combinations-numeric-20261017/snapshot
cd group-combinations-numeric-20261017
```

Use an environment matching `environment.json`; install the archived snapshot
package, including its pyproject metadata. Work in a fresh copy and preserve
recorded outputs by renaming the three `validation-790*.json` and
`fresh-holdout-audit.json` files before rerunning. Then execute:

```bash
python run.py train --seed 7901 --output validation-7901.json
python run.py train --seed 7902 --output validation-7902.json
python run.py train --seed 7903 --output validation-7903.json
python run.py audit --output fresh-holdout-audit.json
python summarize.py
```

Each seed receives exactly 16 fits and rejects an existing output file; there
are no cached-fit resumes. The audit requires all 48 completed recipe entries,
checks source and checkpoint hashes, and freezes validation hashes before use.
A new reproduction has new checkpoint hashes; original recorded checkpoint
binaries are deliberately not published here. Nothing runs when the archive is
rendered or copied into the docs.
